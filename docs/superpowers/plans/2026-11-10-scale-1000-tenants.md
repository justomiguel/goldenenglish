# Phase 8 — Scale to 1000 tenants Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Spec:** `docs/superpowers/specs/2026-11-10-scale-1000-tenants-design.md`
**Depends on:** phases 1–3. The budgets also bind phases 4, 6, 7, 9, and 10.

**Goal:** Tenant resolution, theme reads, migrations, and CI stay inside written budgets at 1000 tenants.

**Architecture:** The existing dynamic tenant cache in `tenantRegistry.ts` gets a 60 s refresh and a 30 s miss cache. The theme cache keys on the published document id. Budgets become unit tests, build checks, and a load test script. The migration apply command runs targets in a bounded pool and resumes from the ledger.

**Tech Stack:** Next.js `unstable_cache`, Server-Timing headers, Node `fetch`, Vitest, Postgres.

## Global Constraints

- Budgets as written in spec section 1. Copy the table into `src/lib/scale/budgets.ts` as constants. Tests read the constants.
- Map refresh: 60 s. Miss cache: 30 s.
- Production reads tenants from Pulsar. `TENANTS_CONFIG_JSON` stays for local and E2E only (rule 19).
- Cache entries hold only the published document and the derived CSS. No drafts.
- Apply command: `--concurrency <n>`, default 8. A failed target does not stop the others. Exit 1 with the failed slugs.
- Load test: no new dependency. 200 synthetic shared-schema tenants. 50 concurrent requests. 5 minutes.
- The load test against a Vercel preview is user-run (rule 32).

## Tasks

### Task 1: Server timing

**Produces:** `export function formatServerTiming(entries: { name: "ge-tenant" | "ge-theme"; durMs: number }[]): string;`

- [ ] Red: `serverTiming.test.ts`. The output is `ge-tenant;dur=1.2, ge-theme;dur=3.4`. Durations are rounded to 1 decimal. Negative values become 0.
- [ ] Green.
  - `src/proxy.ts` measures tenant resolution with `performance.now()` and sets the `Server-Timing` header.
  - A Server Component cannot set a response header. The theme read runs inside the tenant request context (`runWithTenant` in `src/lib/tenant/tenantAls.ts`). It logs `logServerInfo` with scope `theme.read`, `durMs`, and `cache: "hit" | "miss"`.
  - The load test reads the theme duration from those log lines in the isolated stack.

### Task 2: Tenant map refresh and miss cache

**Produces:**

```ts
export function createTenantMapRefreshPolicy(opts: { refreshMs: number; missTtlMs: number; now: () => number }): {
  shouldRefresh(lastLoadedAt: number | null): boolean;
  isMissCached(host: string): boolean;
  recordMiss(host: string): void;
  clearMiss(host: string): void;
};
```

- [ ] Red: `tenantMapRefresh.test.ts` with a fake clock.
  - Refresh is false at 59 s and true at 60 s.
  - A miss is cached for 30 s, then expires.
  - `clearMiss` removes it.
  - The miss map is capped at 5000 hosts, oldest first.
- [ ] Red: `tenantRegistry.refresh.test.ts`.
  - With a stale map, `resolveTenant` triggers one reload and keeps serving the old map while the reload runs.
  - An unknown host triggers one Pulsar lookup, then the cached miss.
  - The lookup failure logs `logServerWarn` with scope `tenant.resolve` and serves the old map.
- [ ] Green. In production, the loader reads Pulsar `platform_tenants` (paged at 1000 rows, rule 13). `TENANTS_CONFIG_JSON` is read only when `GE_DEV_TARGET` is `local` or `e2e`.

### Task 3: Cache key per published version

- [ ] Green. Read `site_themes.published_document_id` first (a small cached read with the tenant tag), then the document with that id in the key.
- [ ] If phase 7 is not done: remove `force-dynamic` from `manifest.ts` and read the cached document.

### Task 4: Apply command pool and resume

- [ ] Red: `runPool.test.ts`.

- [ ] Green. In `apply-migration-all-tenants-pg.mjs`:

### Task 5: Budget checks

- [ ] `budgets.ts` with the spec table as typed constants.
